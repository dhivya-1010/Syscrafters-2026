Stage 04 // Transaction Lifecycle

Payment & Order Design

Temporary inventory reservation locks stock for 10 minutes. If payment succeeds, order confirms; on card failure or payment timeout, stock is immediately replenished or reconciled.

Primary Path: Success (80%) COMMITTED
1. Temporary Stock Reservation (10 min TTL)
↓
2. User Redirected to Payment Gateway
↓
3. Payment Success Callback Verified
↓
4. Order Record Created in Database
↓
5. Order Confirmed & Customer Notified
Fallback Paths: Failure & Timeout RECOVERED
SCENARIO A: PAYMENT REJECTED
Payment Failed → Webhook Triggered
↓
Release Reservation → Stock Returned (+1)
SCENARIO B: PAYMENT TIMEOUT / NETWORK PARTITION
Payment Timeout (TTL Expires)
↓
Verify Payment Status with Gateway API
↓
Reconciliation: If uncharged, release stock. If charged, fulfill order.

Stage 06 // Software Engineering Principles

SOLID & Design Patterns

Mapping battle-tested architectural and structural design patterns to their precise implementation roles within Salestorm.

Design Pattern Where It Is Used in Salestorm Engineering Benefit
Producer-Consumer Purchase Queue (Kafka / RabbitMQ) Absorbs the 10,000 concurrent request shockwave
Strategy Payment Gateways (Stripe, Razorpay, Mock) Swappable processing engines without core code edits
State Reservation & Order Lifecycle Guarantees deterministic state changes (HOLD → PAID)
Idempotency Duplicate Purchase Prevention Protects against double-billing on network retries
Saga Payment + Order Failure Rollback Coordinates distributed transactions across microservices
Outbox Reliable Event Publishing Guarantees DB writes and messaging events commit atomically
Adapter External Payment Gateways & SMS Standardizes vendor SDKs behind uniform interfaces
Circuit Breaker External Downstream Dependencies Fails fast when external payment gateways stall
Repository Data Access Layer Decouples persistence logic from core domain rules
Facade Checkout Orchestrator Provides one unified endpoint for complex checkout sub-calls

Stage 08 // Architectural Balance & Summary

Architecture Decisions & Trade-offs

Decision Trade-off
